Permission boundary

Parent mode is not child capability

Plan read-oriented

  • Denies discovered tools outside allowlist
  • Keeps Task available
  • Resolved Task patterns choose allowed child types
  • Never uses legacy prompt `tools`

Build resolved policy

  • Restores resolved wildcard/tool policy after Plan
  • Does not blanket-allow Task
  • Exact suffix prevents repeated growth
  • Activation + submission share one lock

Child unverified

  • Inheritance semantics are not stable evidence
  • Build badge is provenance only
  • Plan history has leaked terminal denies
  • Mutation requires fresh Build-only parent
Fail-closed operating rule: if a mutating child cannot run its worktree preflight, stop. Do not weaken permissions, switch identity, or replace it with an unrelated root session while claiming native hand-back.
Failure interpretation

The expensive direction is confident fiction

Background card says completed

Only launch returned. Wait for child final turn, process status, or a recognized hand-back.

Do not call child completed

Status entry disappeared

Process ownership is absent. Sessions/transcripts may survive restart; running state does not.

Do not infer idle

No Stop button

The connected process does not positively report the child busy, so cancellation authority is unavailable.

Inspect transcript

Child Bash denied

Parent Plan history may have affected child permissions. Stop and use a fresh Build-only parent.

Do not weaken policy

Older child remains unknown

The 12-child transcript probe budget may be exhausted. Open the child directly and note truncation.
