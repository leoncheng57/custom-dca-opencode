1Executive summary

Your custom OpenHands build's strengths are fine-grained in-app control: per-event notification toggles across 4 channels, MCP health probes with stall diagnosis, agent settings UI, and a panel rail (files / diff / preview / commands / MRs / manager runs). Three headline findings:

  • You've already built ~70% of the notification story for OpenCode — and bidirectional remote control is live: cmux-feed.js auto-loads and round-trips permission approvals / question answers / plan decisions from the cmux Feed back into OpenCode. The gap is granularity and coverage, not capability.
  • Everything worth adding is reachable without forking OpenCode. Config + plugins + custom tools + SDK cover all gaps except a native TUI status bar.
  • The single biggest untapped surface is the cmux Dock (dock.json — doesn't exist on this machine): a right-hand panel rail that can host MCP health, feed, git, and MR watch panes today with zero code.
Flagged during research: opencode.json contains 4 plaintext tokens (2× NOTION_TOKEN, 2× PLAYWRIGHT_MCP_EXTENSION_TOKEN) with .bak copies alongside. Config supports {env:VAR} / {file:path} — you already use it for OpenAI and Figma. Also: logs show deepctl-mcp timing out repeatedly and silently for months — an unreachable MCP taxes every run during tool listing.

5Customizing OpenCode: five tiers, no fork needed

TIER 1
Config — opencode.json + tui.json · 8-level precedence, merged not replaced · models, MCP, permissions, attention/sounds, keybinds
RISK: NONE
TIER 2
Prompt — AGENTS.md, agents/*.md, commands/, skills/, permission rules, policies
RISK: NONE
TIER 3
Plugins — ~30 hooks (session.*, permission.*, tool.execute.*, todo.updated, shell.env, compaction, TUI toasts) + full SDK client · where you already live
RISK: LOW†
TIER 4
Custom tools — tools/*.ts, filename = tool name, any language behind it, can override built-ins
RISK: LOW
TIER 5
SDK / server — @opencode-ai/sdk vs opencode serve: session CRUD, prompts, permission replies, SSE events · an OpenHands-style external panel without touching OpenCode
RISK: LOW-MED
TIER 6
Fork the source — only needed for: native TUI status bar, new TUI panels. You don't need this.
RISK: HIGH

† Tier 3's real risk is silent event-shape drift, not merge conflicts — your plugin already handles permission v1 vs v2 payloads, which is evidence drift happens. Pin @opencode-ai/plugin (done), keep tests (done), log unknown shapes (todo).

6Reconciling with OpenCode updates

  • Tiers 1–2: additive JSON merge; deprecations auto-migrate (legacy theme/keybinds keys were moved to tui.json automatically).
  • Tier 3: mitigate silent drift: log-don't-swallow unknown shapes — cmux-feed.js's bare catch(_){} is the anti-pattern (a failed permission reply is indistinguishable from success).
  • Set "autoupdate": "notify" so an OpenCode upgrade never lands mid-session before you've seen the changelog.

8cmux: the untapped rail

The right sidebar (Dock) is a full panel container on the same surface/split system as the main area. No dock.json exists on this machine. Seed order: .cmux/dock.json (project, trust-gated) → ~/.config/cmux/dock.json. Runtime-scriptable too: cmux new-surface --placement dock; send/read-screen accept dock surface IDs.

Recommended project-local .cmux/dock.json:

{
  "controls": [

      "command": "while true; do clear; date '+%H:%M:%S'; opencode mcp list; sleep 30; done",

    { "id": "feed", "title": "Feed", "command": "cmux feed tui --opentui", "height": 300 },
    { "id": "git",  "title": "Git",  "command": "lazygit", "cwd": "." },
    { "id": "mr-watch", "title": "MRs",

cmux.json cleanups found

  • Migrate notifications.command → notifications.hooks: the current hook string-matches banner body text (*"needs approval"*…) to run say — breaks on any phrasing change. Hooks get structured JSON (agent.category like turn-complete) instead.
  • "sound": "none" makes the brittle say hack the only audio; per-category sounds via hooks are the fix.
  • Delete the byte-identical duplicate action databricks-login-issue-…-2; move one-off task workspaces out of the global palette.
  • Consider suppressOnlyFocusedSurface: true so non-focused agent banners survive when the workspace is merely visible.
  • Recipes 01 / 08 / 09 / 16 are ready-made templates for MCP-health notify, CI progress bars, MR status pills, and a GitLab-ified stale-MR flasher (recipe 19 is stale: calls nonexistent cmux send-surface).

9OpenCode desktop app (installed, 1.18.19)

What it is

Electron (migrated off Tauri). The full opencode server compiled in as a sidecar utility process — same code the CLI runs, basic-auth on a per-launch password. Can also attach to an external opencode serve.

What it adds

Tabs (persisted), project/session home, timelines w/ revert & fork, settings UI for providers / MCP state / agents, embedded terminal, review/diff panel, native macOS notifications with 10 bundled alert sounds, oc:// deep links.

Config compatibility

Reads your ~/.config/opencode/opencode.json unchanged (only XDG_STATE_HOME is redirected). All 21 MCP servers and all 4 plugins load as-is; login-shell PATH is honored.

Two caveats

1) cmux plugins lose context when launched from Finder (no CMUX_SURFACE_ID). 2) Notification double-delivery is real — see Fig 5.

Verdict: closest packaged thing to your OpenHands UI (tabs + session mgmt + MCP/provider settings UI + native notifications) at zero build cost — worth a 20-minute trial pointed at an external server started inside cmux so the cmux plugins keep their env.
